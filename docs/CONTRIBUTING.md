# Contributing

## Workflow
1. Start from an updated `main`.
2. Create a focused branch, e.g. `feature/emotion-adapter` or `fix/config-validation`.
3. Add or update tests with behavior changes.
4. Run relevant checks locally.
5. Open a pull request describing purpose, risk, test results, and rollback considerations.
6. Merge only after required checks pass.

## Commit conventions
Use clear imperative messages, e.g. `docs: define initial architecture`, `feat: add emotion adapter contract`, `test: cover mixed emotion transitions`, or `fix: validate tool arguments`.

Do not commit real credentials, machine-specific paths, model weights, personal sensor recordings, generated caches, or unrelated build outputs.
